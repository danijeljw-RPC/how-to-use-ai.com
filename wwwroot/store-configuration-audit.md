## What you need to set up

### 1. Email Sending in Cloudflare

Onboard/verify `how-to-use-ai.com` for **Email Sending**, complete required DNS authentication and inspect verified status in Dashboard using an account with access. Email Routing alone is insufficient. Add this top-level binding to wrangler.jsonc:

```json
"send_email": [{ "name": "STORE_EMAIL", "allowed_sender_addresses": ["hello@how-to-use-ai.com"] }]
```

For an initial controlled test you can additionally restrict `allowed_destination_addresses` to real inboxes you control. Remove that restriction before serving general customers. Purchase support remains `/contact/`; sign-in and purchase emails are still required.

### 2. Worker secrets

Run from wwwroot and paste values into the prompts; never put these in public `vars` or commit them:

```sh
npx wrangler secret put STORE_SIGNING_SECRET
npx wrangler secret put STRIPE_SECRET_KEY
npx wrangler secret put STRIPE_WEBHOOK_SECRET
```

- `STORE_SIGNING_SECRET`: cryptographically random secret, at least 32 characters; generate and keep it securely.
- `STRIPE_SECRET_KEY`: your Peach Freestyle **test** secret/restricted key (`sk_test_` or `rk_test_`). Restricted keys need the Checkout/product/price/payment/charge permissions described in store-setup.md.
- `STRIPE_WEBHOOK_SECRET`: the `whsec_...` from the new website endpoint below, not the licence server's or a local Stripe listener's secret.

Secret puts immediately deploy Worker versions; they do not rebuild/upload your changed local source/config. Complete the final build/deploy below.

### 3. Stripe test webhook

In the same Stripe test account, create an endpoint at:

`https://how-to-use-ai.com/api/stripe/webhook/`

Subscribe to:

- `checkout.session.completed`
- `checkout.session.async_payment_succeeded`
- `checkout.session.async_payment_failed`
- `checkout.session.expired`
- `charge.refunded`
- `charge.dispute.created`

Copy that endpoint's signing secret into the Worker secret. Preserve existing endpoints. A CLI test login does not configure the deployed Worker automatically.

### 4. Controlled activation and deployment

For a digital run-through on this HTTPS website, keep `STORE_MODE=test` and `STORE_SIGNED_ENABLED=false`. After email domain verification, binding and secrets are configured, set `STORE_EMAIL_READY=true` to exercise login delivery. Leave `COMMERCE_ENABLED=false` for that first email test; auth can operate separately from checkout. If real inbox delivery fails, turn the ready flag back off and fix delivery.

After login works, set `COMMERCE_ENABLED=true` **while keeping test mode** and deploy for the payment run-through. This exposes test checkout on the public website; a separate HTTPS test hostname/Worker/database is preferable if visitors should not see it. Do not switch to live keys for this test.

```sh
npm run cf-typegen
npm run check
npm test
npm run build
npx wrangler deploy
```

Build first: Astro deployment uses generated `dist/server/wrangler.json`; deploying a stale build will omit new source settings. A successful dry-run proves packaging, not email delivery or payment fulfilment.

## Run-through

1. Open `/downloads/`, use a real inbox you control, complete Turnstile and receive the login email. Confirm the link on its landing page.
2. Buy PDF + EPUB in AUD from the verified library. In Stripe test Checkout use `4242 4242 4242 4242`, any future expiry and any three-digit CVC. No real charge occurs in test mode.
3. Confirm Stripe shows a paid test session and successful webhook delivery; then refresh the library and download both files. Open them in readers to check content.
4. Check the purchase email arrives. Try buying an owned format again: it should be blocked. Reload after ten minutes to obtain fresh download links.
5. Refund the test payment in Stripe and confirm those downloads lose access. Use another controlled address to test individual formats or failure scenarios.
6. Disable `COMMERCE_ENABLED` again after the public test if sales should remain closed. Live launch needs live Products/key/webhook together plus the merchant's tax, policy and operational setup.
