# ADR-03-0011 — Repeated Notes Reuse Their Number; Dead Sources Cite an Archived Copy

## Status

Accepted

## Date

2026-10-05

## Area

Publishing

## Context

Before upload to KDP, a check of the release build found that pandoc prints a footnote's full text every time its label is cited. In Book 1, 57 notes were cited more than once (63 repeat citations), so the back-of-book Notes printed the same source up to four times in a chapter (for example Chapter 12 notes 33 and 34). The same check found two cited pages that no longer exist: Humane's Ai Pin FAQ (domain gone) and Builder.ai's "Natasha" page (site offline).

The author asked for both to be fixed using the recommended approach.

## Decision

1. **A repeated citation reuses the note's first number.** Within a chapter, the first citation of a note prints it; later citations of the same note show the same number and print nothing new. `publishing/pandoc/book.lua` does this for every output: `\hwNoteRemember`/`\hwNoteAgain` in LaTeX (print, PDF ebook, drafts), a link to the existing note in EPUB. Numbering still restarts each chapter. A note cited in two chapters is printed once in each.
2. **Authors keep citing naturally.** The manuscript may cite the same `[^label]` as often as the text needs; no manuscript edit is required to avoid repeats.
3. **A dead source cites an archived copy.** When a cited page no longer exists, the note keeps its original description and links a Wayback Machine snapshot, stating the archive date. The snapshot must be checked to show the content the note relies on.

## Consequences

- Book 1's paperback interiors fell from 414 to 406 pages; spines narrowed (KDP 0.9143 in, IngramSpark 1.0150 in) and covers are regenerated by the build.
- `tests/test_book_lua_repeated_notes.py` covers the LaTeX and HTML behaviour.
- Supersedes nothing; implements the endnote model in ADR-04-0003 and the release build in ADR-03-0008.
