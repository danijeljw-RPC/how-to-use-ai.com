# OI-0001 — Public Preview File for the Launch Site

## Status

Open

## Date Opened

2026-09-24

## Area

Publishing

## Question

Which file should the launch site's "Read today's preview" links serve, and where should it be hosted?

## Why This Matters

The home, book, preview, purchase, and checkout-cancel pages all link to `/api/preview/`. That endpoint redirects to `PREVIEW_DOWNLOAD_URL`, which is not set. Until it is, visitors who follow those links see a controlled "The preview is temporarily unavailable" page on the live site.

## Current Assumptions

- The existing draft PDFs are internal review editions (`ADR-03-0002`). They are not approved for public distribution, so none was published automatically.
- The preview must be a stable HTTPS URL. The site redirects to it; it does not store or generate the file.

## Options

### Option 1 — Publish a dedicated preview excerpt

Produce a short public excerpt PDF, such as the opening chapter, host it on Cloudflare R2 or as a static site asset, and set `PREVIEW_DOWNLOAD_URL`.

Pros:

- Controls exactly what is public.
- Fixes the dead-end links.

Cons:

- Needs an excerpt build and an author decision on what it contains.

### Option 2 — Hide the preview links until a file exists

Change the pages so preview calls to action render only when `PREVIEW_DOWNLOAD_URL` is configured.

Pros:

- No dead ends for visitors in the meantime.

Cons:

- A code change, and the launch pages lose their main call to action for now.

## Recommendation

Option 1 as soon as the excerpt content is chosen. Option 2 is worth doing if the preview will be unavailable for more than a few days.
