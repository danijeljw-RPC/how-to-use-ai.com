# OI-0005 — Print Readiness of the Assembled Book PDF

## Status

Open

## Date Opened

2026-09-30

## Area

Publishing

## Question

What else must change before the assembled book PDF can go to a print service?

## Why This Matters

The covers are now vector PDF with embedded fonts (ADR-03-0002, amended
2026-09-30), but that alone doesn't make the book print-ready. Print services
run preflight checks and reject files that fail them.

## Known Gaps

1. **Unembedded fonts on the generated pages.** `scripts/assemble_draft_book.py`
   draws the notice page and the end-of-preview page with the ReportLab base
   fonts Helvetica and Helvetica-Bold, which are not embedded. `pdffonts
   dist/30-books/31-book-01.pdf` lists both with `emb no`. The fix is to register and use
   the same embedded Arial fonts the cover renderer uses.
2. **Bleed.** Pages are exactly 7 x 10 inches with no bleed. Most printers want
   0.125 inches of bleed on full-colour covers, and the back cover's accent bars
   and navy band run to the edge.
3. **Colour space.** Everything is RGB. Some printers need CMYK or a specific
   output intent.
4. **Print cover layout.** A printed paperback or hardcover needs a single
   wrap-around cover (back, spine, front) sized to the page count and paper, not
   separate front and back pages inside the interior PDF.
5. **Internal review wording.** The back cover always says "Internal review
   edition / Not for sale or public distribution", including on preview editions
   published to the site with `--webpub`.

## Decision Needed

Which print service (and which of its specifications) to target, so gaps 2–4
can be fixed against a real specification rather than guessed.
