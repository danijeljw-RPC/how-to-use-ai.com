# Convenience, Capability and Cognitive Offloading

This is the conceptual bridge between the practical chapter material and the lighter over-reliance section.

# Convenience versus capability

## Convenience

AI makes the current task easier:
- packing list;
- routine message;
- remove photo distraction;
- summarise a letter;
- group a shopping list.

## Capability

AI helps the person become more able:
- understand compound interest;
- practise a language;
- learn why an answer is wrong;
- critique reasoning;
- learn how to structure a complaint;
- learn a cooking or photography technique.

They are not mutually exclusive.

A generated meal plan may be pure convenience. An explanation of why meals were grouped around overlapping ingredients can teach a reusable method.

# Cognitive offloading

Risko and Gilbert (2016) define cognitive offloading as using physical action/external resources to reduce internal cognitive demand.

AI did not invent it.

Humans already externalise cognition into:
- notes;
- reminders;
- calendars;
- maps;
- calculators;
- search engines;
- navigation systems.

Therefore:
> using a tool so you do not have to remember or calculate everything yourself is not evidence of cognitive decline.

# Evidence that offloading can help

Burnett and Richmond's 2026 meta-analysis examined memory-based cognitive offloading.

The published abstract reports that offloading:
- improved performance under multiple experimental conditions;
- reduced interindividual variability.

This is important counterevidence to a simplistic “offloading is bad” narrative.

It does **not** answer which kinds of thinking should be delegated to GenAI. That remains task-dependent.

# Supporting versus substituting cognition

## Support
AI removes burden while the person remains cognitively involved.

Example:
- user states their own view;
- AI challenges it;
- user evaluates the challenge.

## Substitute
AI produces a conclusion and the person accepts it without engaging.

Example:
- user asks which course to study;
- AI names one;
- user acts without investigation.

Substitution is not automatically harmful for every low-stakes task. Relevance depends on:
- consequence;
- reversibility;
- need to learn;
- personal ownership.

# Performance is not necessarily learning

Yan et al. explicitly distinguish performance gains with GenAI from learning.

Examples:
- AI writes a good email; user has not necessarily become a better writer.
- AI fixes a spreadsheet; user has not necessarily learned the formula.
- AI identifies a plant; user has not necessarily learned identification.

This is not a reason not to use AI.

It is a reason to distinguish:
> Do I want the task completed, or do I want to become able to perform it?

# Task matrix

| Task | Useful offloading | Human capability/judgement worth retaining |
|---|---|---|
| Packing list | memory burden | final personal check |
| Grocery grouping | organisation | dietary choices |
| Routine email | phrasing | intent/facts |
| Language practice | examples/feedback | retrieval/speaking |
| Parenting decision | information gathering | parental judgement |
| Investment decision | research organisation | verification/decision |
| Study choice | option mapping | goals/final decision |

# Better question for readers

Instead of:
> Am I relying on AI too much?

Ask:
> Which part of this task am I asking AI to take over?

Possible answers:
- remembering;
- formatting;
- options;
- explanation;
- first draft;
- checking;
- judgement;
- final decision.

That makes over-reliance concrete.
