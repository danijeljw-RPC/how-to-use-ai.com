# Accessibility Support

This section deserves more weight than the current draft gives it.

The central editorial idea:

> A feature that saves one user thirty seconds may give another user meaningful independence.

# Vision impairment

## Be My Eyes and visual AI

OpenAI's Be My Eyes case study describes GPT-powered visual assistance for blind and low-vision users.

Underlying tasks include:
- identify products;
- interpret visual scenes;
- understand photographs;
- inspect labels or objects.

This is a strong example of AI increasing capability rather than merely convenience.

Caveat:
The source is a company/customer case study. Describe demonstrated uses, not promotional accuracy claims as independent evidence.

## Microsoft Seeing AI

Microsoft documents a free app designed for blind and low-vision users that can:
- read text/documents;
- identify products;
- recognise currency;
- describe photographs;
- provide richer generative descriptions;
- answer questions about scanned documents.

## Copilot Vision with screen readers

Microsoft's accessibility documentation describes using Copilot Vision with Narrator, JAWS and NVDA so users can ask questions about visible app/browser content and hear responses.

# Literacy and cognitive accessibility

AI can:
- simplify dense text;
- explain a letter in plain language;
- break instructions into steps;
- summarise;
- turn a document into a checklist;
- answer questions about supplied text.

Potential benefit:
- lower reading load;
- provide another route into difficult information.

Important caveat:
**simplification can omit nuance**. For important documents, the original remains primary.

# Language barriers

AI can:
- explain a message;
- draft a reply;
- translate;
- convert formal wording to plain language.

Do not treat general AI translation as authoritative for legal, medical or contractual meaning.

# Hearing impairment

AI-enabled uses include:
- transcription;
- captions;
- speech-to-text;
- translated calls/conversations;
- recording summaries.

# Mobility limitations

Voice interaction can reduce reliance on typing or precise touch:
- dictate messages;
- ask questions about a screen;
- structure a list;
- retrieve information by voice.

Accessibility varies by device, product and setup, so avoid claiming a general AI interface meets every access requirement.

# Strong chapter example

A sighted reader might use image AI to identify an unfamiliar object because it is convenient.

A blind user might use visual assistance to:
- read a product label;
- distinguish packages;
- understand a photograph;
- inspect a menu or receipt.

Same broad capability; very different significance.

# Chapter-5-style request examples

## Image description

### Weak
> What's in this picture?

### Stronger
> Describe this photograph for someone who cannot see it. Start with the overall scene, then list important people, objects and visible text. If text is unclear, say that rather than guessing.

Provides:
- audience;
- structure;
- uncertainty instruction.

## Document assistance

> Read this letter and tell me, in plain language, what action it appears to ask me to take. Then point me to the wording that supports each action so I can check it myself.

This deliberately keeps verification possible.
