# Chapter 9 Research — Publication Recheck Checklist

**Baseline research date:** 2026-10-01  
**Purpose:** Items whose status, wording, figures, or practical advice can change between research and manuscript publication.

This file is deliberately separate from the research notes so the later writing/editing system can run a final verification pass without redoing the entire research project.

## Priority key

- **High** — verify at manuscript lock; likely to change or legally important.
- **Medium** — verify if cited numerically or used as a current example.
- **Low** — historical/academic source is relatively stable, but confirm bibliographic details and avoid implying it measures the present.

## 13. Numerical-claim audit

Before publication, make a table of **every number actually used in Chapter 9** and check:

- [ ] Exact wording in the original source.
- [ ] Source date.
- [ ] Population/jurisdiction.
- [ ] Numerator and denominator.
- [ ] Whether it is observed data, reported data, survey evidence, estimate, forecast, scenario model, company operational data or academic finding.
- [ ] Whether reports/complaints undercount the true total.
- [ ] Whether the number is AI-specific or a broader category that includes non-AI activity.
- [ ] Whether a percentage uses the correct comparison period.
- [ ] Whether the figure has been superseded by a newer annual dataset.
- [ ] Whether the chapter uses the number to support more than the source actually establishes.

---

## 14. Case-study audit

For every real-world example used:

- [ ] Prefer the original regulator, court, academic paper, government source or company filing where available.
- [ ] Confirm date and current procedural/legal status.
- [ ] Separate allegation from finding.
- [ ] Separate company claim from independent verification.
- [ ] Do not identify private victims unnecessarily.
- [ ] Do not include sexual/exploitative detail beyond what the educational point requires.
- [ ] State whether the example demonstrates capability, prevalence, impact, a failed safeguard, a successful safeguard, or a regulatory response.
- [ ] Do not imply one dramatic case is representative of frequency.

---

## 15. Cross-chapter scope audit

- [ ] **Chapter 8:** Do not repeat the creative copyright debate in depth; Chapter 9 should treat copyright mainly as unresolved risk/uncertainty and ordinary-user implications.
- [ ] **Chapter 10:** Do not turn concentration, automation or bias into a jobs-replacement chapter.
- [ ] **Chapter 11:** Keep AGI/catastrophic-risk and hype/doom arguments principally there; Chapter 9 is about concrete current risks and near-term evidence.
- [ ] **Chapter 13:** Avoid duplicating scams **about buying AI products**; Chapter 9 focuses on AI **used as a tool in scams**.
- [ ] **Later technical books:** Prompt injection, model security architecture, adversarial ML and detailed system mitigations should remain high-level here.

## 16. Final wording traps to search for

Run a manuscript search for statements equivalent to these and qualify them unless the evidence supports the exact wording:

- [ ] “AI misinformation has changed election outcomes.”
- [ ] “Deepfakes are illegal.”
- [ ] “You can tell a deepfake by looking closely.”
- [ ] “AI detectors can reliably tell what is AI-generated.”
- [ ] “AI scams caused $X billion in Australian losses.”
- [ ] “Only older/gullible people fall for scams.”
- [ ] “AI is objective.”
- [ ] “Facial recognition is accurate now.”
- [ ] “Facial recognition is illegal in Australia.”
- [ ] “Companies do not train on the data, therefore it is private.”
- [ ] “Deleting a chat deletes every copy immediately.”
- [ ] “AI is unregulated.”
- [ ] “Copyright law says AI training is legal/illegal.”
- [ ] “Every AI query uses X energy/water.”
- [ ] “Data centres use X TWh, therefore AI uses X TWh.”
- [ ] “AI is controlled by only a few companies.”
- [ ] “Open source fixes concentration.”
- [ ] “Regulation will prevent the harms.”

## Recommended final publication-state note

The manuscript does not need to tell readers that every line was rechecked. The project should, however, retain a dated internal record showing when the volatile claims above were last verified. This is particularly valuable for the companion website, where current figures and product settings can be updated without waiting for a new book edition.
