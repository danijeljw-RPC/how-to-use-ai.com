# OI-0001 — Callout Naming Reconciliation Between Legacy Chapter 1 Draft and Current Style Guide

## Status

Open

## Date Opened

2026-09-21

## Area

Book 1

## Question

The legacy Chapter 1 draft (`legacy-data/book1-part1-chapter1-draft.md`) used a different callout naming set than `docs/04-style/callout-guide.md`. Most legacy types map cleanly onto the baseline set, but one — **Reference** — does not, and one — **Personal Reflection** — maps onto a placeholder pattern rather than a callout type. Should the baseline callout system be extended, or should these be folded into existing types as done in this reconciliation pass?

## Why This Matters

Chapter 1 is where the callout system is defined for the rest of the series (`CLAUDE.md` §Callout Types, ADR-02-0001 §Callout System Requirement). Getting the mapping wrong here means every later chapter inherits the same gap or the same forced-fit.

## Current Assumptions (Applied in This Migration)

The migration into `docs/02-book-01/chapters/chapter-01-youve-already-been-using-ai.md` used the following mapping, treated as a small reversible assumption per `CLAUDE.md`'s "Handling Ambiguity" rule:

| Legacy type | Baseline type used | Notes |
|---|---|---|
| Note | Plain English | Both are "helpful clarification" — reasonable fit. |
| Warning | Watch Out | Direct match. |
| Reference | Plain English | **Weakest mapping** — legacy "Reference" was used for term definitions and pointers to later material, not just beginner translation. Folding it into Plain English works for Chapter 1 but may not scale to chapters with heavier definitional or cross-reference needs. |
| Personal Reflection | Author reflection placeholder (`> [Author reflection placeholder: ...]`) | Not a callout — uses the dedicated placeholder pattern from `CLAUDE.md`/`docs/04-style/style-guide.md` instead, since that pattern already exists specifically for author stories and the baseline "Author Note" callout is defined for asides, not placeholders. |
| Try This | Try This | Direct match. |
| Myth vs Reality | Myth vs Reality | Direct match. |
| Diagram Opportunity | Diagram placeholder (`> [Diagram placeholder: ...]`) | Not a callout — uses the dedicated diagram placeholder pattern. |

## Options

### Option 1 — Keep the baseline set as-is, fold Reference into Plain English permanently

Pros:

- No new callout type to maintain across the series.
- Plain English already covers most Reference use cases (term definitions).

Cons:

- Loses the "pointer to later chapter or companion material" function Reference sometimes served.
- Plain English becomes a catch-all, diluting its meaning ("translate technical concept") for definitional/pointer content.

### Option 2 — Add a dedicated "Reference" callout type to the baseline set

Pros:

- Preserves a clean distinction between "translate a concept" (Plain English) and "define a term or point elsewhere" (Reference).
- Matches what the legacy draft was already doing successfully.

Cons:

- Adds an eighth+ callout type this early in the series — more for readers to learn.
- Requires an ADR (style/terminology decisions are ADR-level per `CLAUDE.md`) and a `docs/04-style/callout-guide.md` update before later chapters are drafted.

## Recommended Next Step

Author review: confirm whether Option 1 (current working assumption, already applied to Chapter 1) or Option 2 should stand. If Option 2, file an ADR under `docs/04-style/decisions/` and update `docs/04-style/callout-guide.md` before Chapter 2 is drafted.
